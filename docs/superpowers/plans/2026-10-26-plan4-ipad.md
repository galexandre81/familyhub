# Plan 4 — iPad de cuisine : tableau, mode recette, minuteur — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remplacer la grille de 10 cases de l'iPad par un tableau fixe centré sur « qu'est-ce qu'on cuisine », un mode recette « toute la recette d'un coup » avec minuteur à droite, et un minuteur lançable en un toucher, aux couleurs et polices du design system.

**Architecture:** L'app display (ES5, iPad mini 1, iOS 9) garde son socle (appairage, snapshot, minuteurs partagés, overlay). Le serveur continue d'alimenter les tuiles du `layout` de l'écran (on garde le `layout` comme liste invisible des sources de données : météo, agenda, menu, recette du jour, radio, minuteur, réglages, livre). Un nouveau module `tableau.js` remplace le rendu en grille et lit les données par **type** de tuile. Le prochain repas est calculé sur l'iPad à partir du snapshot du menu de la semaine et des heures de repas du foyer (port ES5 testé de la logique du hub). Les recettes complètes sont lues dans Firestore à l'ouverture du mode recette.

**Tech Stack:** JavaScript ES5 + Firebase SDK v8 (iPad), CSS sans variables/gap/grid, polices woff locales, Cloud Functions v2, React (hub, éditeur d'écran), Vitest (logique pure, y compris fichiers ES5 chargés via `node:vm`).

**Spec:** `docs/superpowers/specs/2026-10-25-refonte-ipad-mobile-design.md` (§4, §7, §8 bis « Données de l'iPad », « Livraison », « Minuteurs »).

## Global Constraints

- `apps/display/public` : ES5 strict (syntaxe ET fonctions intégrées iOS 9) ; CSS sans `var(`, `gap`, `display: grid` ; `npm run check:display` (ES5, CSS, fichiers) doit passer.
- Écran cible 1024×768 (paysage) ; cibles tactiles ≥ 72 px ; texte ≥ 20 px ; une seule chose en jaune « maintenant » par écran (le prochain repas) ; icône + mot ; 2 lignes max, le reste replié.
- Couleurs et polices : jetons de `@family-hub/design` (jour/nuit), Bricolage Grotesque (titres) + Atkinson Hyperlegible (texte) en **woff** hébergé sous `/display/fonts/`.
- Ordre d'usage (réponse du propriétaire) : prochain repas > recette et minuteur pendant la cuisine > météo > agenda de la semaine > livre de recettes ; radio rarement ; liste de courses jamais sur l'iPad.
- Mode recette : toute la recette d'un coup ; colonne gauche (≈ 2/3) = étapes, seule à défiler ; colonne droite fixe = ingrédients/quantités en haut, minuteur en dessous ; « Lancer N min » sur les étapes avec durée ; même écran depuis le prochain repas, le menu et le livre.
- Minuteur : 1, 5, 10 min et « Autre » ; pas de nom à taper ; « +1 min », pause, arrêter ; alarme visible par-dessus tout écran jusqu'à « OK » ; partagé avec les téléphones (même forme de document que le hub).
- Heures des repas : `parametres.heuresRepas` du foyer, défauts 07:00 / 08:00 week-end, 12:15, 19:00 ; un repas reste « prochain » jusqu'à 1 h après son heure.
- Rien ne doit casser un iPad allumé pendant le déploiement : les nouveaux fichiers sont chargés via `index.html` versionné (plan 1) ; l'iPad recharge seul.
- Textes français, tutoiement. Aucun déploiement. Commits : trailer `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.

## Review Focus

- Snapshot du menu absent, vide ou périmé (pas de plan actif, plan fini) : le tableau affiche « Pas de menu en cours » sans planter, les autres blocs restent — test de `prochainsRepas` ES5 sur entrées vides et rendu défensif.
- Réseau coupé pendant l'ouverture d'une recette : recettes déjà vues reprises du cache mémoire, sinon message « Recette indisponible sans réseau » et minuteur toujours utilisable — test de l'assemblage avec recette manquante.
- Minuteur terminé pendant qu'une recette, le livre ou le menu est ouvert : le bandeau d'alarme est au-dessus et « OK » l'arrête — z-index et test manuel (vérification décrite).
- Changement de jour (minuit) et bascule jour/nuit pendant que l'iPad reste allumé : recalcul chaque minute sans rechargement — test des fonctions pures avec des heures aux bornes.
- Tuile attendue absente du `layout` (ex. pas de tuile météo) : le bloc concerné indique « À configurer dans le hub » au lieu de disparaître ou de planter.
